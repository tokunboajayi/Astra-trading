# Project instructions

Rich-HER: a trading simulator that teaches women to start investing before they feel ready.
Python/FastAPI backend, vanilla JavaScript frontend, no build step.

## Commands — always use these

```bash
python dev.py setup     # once
python dev.py run       # start the app on http://127.0.0.1:8000
python dev.py test      # 197 tests
python dev.py check     # tests + fixtures + browser. Run before committing.
```

`dev.py` always uses `.venv` (the project's own private copy of Python's packages). **Never suggest bare `pytest` or `uvicorn`** — running those with the system Python instead fails with confusing errors that look like real bugs but aren't.

## Tech stack

| Layer | What |
|---|---|
| Backend | Python 3.10+, FastAPI, Uvicorn |
| Rules | `sim_engine.py`, `story_engine.py` — standard library only, no third-party imports |
| Frontend | Vanilla JS ES modules, SVG, CSS. No React, no TypeScript, no bundler. |
| Tests | pytest (197 tests), plus a headless-browser run (59 checks) |
| Data | Synthetic fixtures generated by `scripts/build_fixtures.py` |

## The rule that explains every design decision

**The browser never calculates anything about money.** Not the price, not the fill, not the P&L (profit and loss), not the ending. Every action posts to the server, the server recalculates everything, and the response carries the complete new state (`snapshot()`), which the browser re-renders from scratch.

If you are about to write `price * quantity` in a `.js` file — stop. That number comes from the server.

## Structure

```
server/
  sim_engine.py      market maths. Pure: no I/O, no clock, no randomness.
  story_engine.py    scenes, flags, endings. Pure, same contract.
  main.py            session + HTTP. 749 lines, 13 labelled sections - grep "^# ---"
  tests/
web/                 one file per component; content in .json, not code
fixtures/*.json      generated, never hand-edited
scripts/             build_fixtures.py, e2e-browser.mjs
docs/                SPEC_3.md (current), WORKFLOW.md, archive/ (superseded)
```

**Pure engines stay pure.** Never add a file read, a network call, a clock, or `random` to `sim_engine.py` or `story_engine.py`. If something needs those, it belongs in `main.py` instead.

## Code style

- Python: snake_case, 4 spaces, lines under ~110 characters. Docstrings explain *why*, not *what*.
- JavaScript: camelCase, 2 spaces, ES modules. Build DOM elements with `h()` from `format.js`.
- Keep functions under 50 lines and files under 800.
- Handle errors explicitly; never swallow one silently.
- Every user-facing error carries a plain-English `message` written for the person using the app, not for a developer.

## Content lives in JSON, not code

`web/coach.json`, `web/scenes/*.json`, `web/tiers.json`, and `web/checks.json` hold the words and the rules. Both the server and the browser read them, so the screen and the server can never disagree. **You can change wording without touching a `.py` or `.js` file.**

## The tests are strict about words

`test_scenes.py` fails the build when content breaks a product principle:

- an "I don't know" / skip / unsure option appears anywhere
- any scoring field appears anywhere (`score`, `points`, `grade`, `rank`, `xp`…)
- a named loss has no next step alongside it
- a drawdown (a value drop) scene has no recovery scene after it
- a scene is a dead end, or a `goto` (a link to another scene) points nowhere
- **any dollar figure drifts from what the fixture actually produces**

These checks are deliberate. Don't weaken a test just to make content pass — fix the content instead.

## Fixtures

Generated and deterministic (same input always produces the same output). **Never hand-edit a file in `fixtures/`.** Change `scripts/build_fixtures.py` instead, then run `python dev.py fixtures`. All six companies are fictional (HLX, BRW, BRD, KIN, NVX, VLT) and every price is synthetic.

## Offline is enforced

No CDN, no web fonts, no requests to any external server. `scripts/e2e-browser.mjs` fails the build if anything tries to reach googleapis/gstatic/cdn, or if any request comes back 404. The venue demo runs with Wi-Fi off — **do not add a dependency on the internet.**

## Design tokens

`web/tokens.css` loads before `index.css`. Use the CSS variables it defines, never a raw hex color. There are two surfaces: warm `--paper-*` is the room where the coach lives, and dark `--ink-*` is the market stage. Text colors are paired to their background (`--text-on-ink` on ink, `--text` on paper), and every pairing has been checked for a contrast ratio of at least 4.5:1 (the accessibility standard for readable text).

## Git

Use conventional commits (`feat:`, `fix:`, `docs:`, `test:`). Work on a branch — never commit straight to `main`. Run `python dev.py check` before committing.
