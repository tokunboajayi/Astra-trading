# Project instructions

Rich-HER: a trading simulator that teaches women to start investing before they feel ready.
Python/FastAPI backend, vanilla JavaScript frontend, no build step.

## Commands — always use these

```bash
python dev.py setup     # once
python dev.py run       # start the app on http://127.0.0.1:8000
python dev.py test      # 192 tests
python dev.py check     # tests + fixtures + browser. Run before committing.
```

`dev.py` always uses `.venv`. **Never suggest bare `pytest` or `uvicorn`** — on the system
Python those fail with confusing errors that look like real bugs.

## Tech stack

| Layer | What |
|---|---|
| Backend | Python 3.10+, FastAPI, Uvicorn |
| Rules | `sim_engine.py`, `story_engine.py` — standard library only, no imports |
| Frontend | Vanilla JS ES modules, SVG, CSS. No React, no TypeScript, no bundler. |
| Tests | pytest (192), plus a headless-browser run (59 checks) |
| Data | Synthetic fixtures generated by `scripts/build_fixtures.py` |

## The rule that explains every design decision

**The browser never calculates anything about money.** Not the price, not the fill, not the
P&L, not the ending. Every action posts to the server, the server recalculates everything,
and the response carries the complete new state (`snapshot()`), which the browser re-renders
from wholesale.

If you are about to write `price * quantity` in a `.js` file — stop. That number comes from
the server.

## Structure

```
server/
  sim_engine.py      market maths. Pure: no I/O, no clock, no randomness.
  story_engine.py    scenes, flags, endings. Pure, same contract.
  main.py            session + HTTP. 725 lines, 13 labelled sections - grep "^# ---"
  tests/
web/                 one file per component; content in .json, not code
fixtures/*.json      generated, never hand-edited
scripts/             build_fixtures.py, e2e-browser.mjs
docs/                SPEC_3.md (current), WORKFLOW.md, archive/ (superseded)
```

**Pure engines stay pure.** Never add a file read, a network call, a clock or `random` to
`sim_engine.py` or `story_engine.py`. If something needs those, it belongs in `main.py`.

## Code style

- Python: snake_case, 4 spaces, ~110 char lines. Docstrings explain *why*, not *what*.
- JavaScript: camelCase, 2 spaces, ES modules. Build DOM with `h()` from `format.js`.
- Functions under 50 lines, files under 800.
- Handle errors explicitly; never swallow one silently.
- Every user-facing error carries a plain-English `message` written for the user.

## Content lives in JSON, not code

`web/coach.json`, `web/scenes/*.json`, `web/tiers.json`, `web/checks.json` hold the words and
the rules. Both the server and the browser read them, so the screen and the server cannot
disagree. **Change wording without touching a `.py` or `.js` file.**

## The tests are strict about words

`test_scenes.py` fails the build when content breaks a product principle:

- an "I don't know" / skip / unsure option appears anywhere
- any scoring field appears anywhere (`score`, `points`, `grade`, `rank`, `xp`…)
- a named loss has no next step beside it
- a drawdown scene has no recovery scene after it
- a scene is a dead end, or a `goto` dangles
- **any dollar figure drifts from what the fixture actually produces**

These are deliberate. Do not weaken a test to make content pass — fix the content.

## Fixtures

Generated and deterministic. **Never hand-edit a file in `fixtures/`.** Change
`scripts/build_fixtures.py`, then `python dev.py fixtures`. All six companies are fictional
(HLX, BRW, BRD, KIN, NVX, VLT) and every price is synthetic.

## Offline is enforced

No CDN, no web fonts, no external requests. `scripts/e2e-browser.mjs` fails the build if
anything reaches googleapis/gstatic/cdn, or if any request 404s. The venue demo runs with
Wi-Fi off — **do not add a remote dependency.**

## Design tokens

`web/tokens.css` loads before `index.css`. Use the variables, never a raw hex. Two surfaces:
warm `--paper-*` is the room where the coach lives, dark `--ink-*` is the market stage. Text
colors are paired to their ground (`--text-on-ink` on ink, `--text` on paper) and every pair
is verified at 4.5:1 or better.

## Git

Conventional commits (`feat:`, `fix:`, `docs:`, `test:`). Work on a branch, never commit
straight to `main`. Run `python dev.py check` before committing.
